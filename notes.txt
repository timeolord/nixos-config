user preferences

working and validation guidance

edit shared system behavior in config.nix, shared home behavior in home.nix, a specific application in programs/, host hardware in its matching file, and desktop behavior in hyprland/. update this reference when those relationships change.
review git status before and after work because application path units can modify tracked files in the background. do not replace unrelated local changes.
for future configuration changes, evaluate an explicit host first: nix eval --no-write-lock-file .#nixosConfigurations.melkmobile.config.system.build.toplevel.drvPath
to build without activating: nix build --no-link --no-write-lock-file .#nixosConfigurations.melkmobile.config.system.build.toplevel
replace melkmobile with the intended host and check all four for shared changes. iso outputs can be built as .#melkmobile-iso. these commands were documented, not executed during this review.
new source files referenced by a git flake must be included in its git source set for evaluation. keep lockfile changes intentional. a build does not verify desktop behavior, secret activation, or host hardware at runtime.
