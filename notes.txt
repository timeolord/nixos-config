repository reference

the system configuration includes the hyprland and codex cli cachix substituters and signing keys. the caches take effect after activation; a running build does not automatically switch to them. cache availability depends on the exact derivation.
rebuild-tools.nix generates rebuild-system and its preflight from rebuild.sh and rebuild-preflight.py, using nix.settings.substituters and nix.settings.trusted-public-keys as the only cache lists. after activation rb invokes rebuild-system. the source rebuild.sh remains a bootstrap and evaluates the target cache settings when not run through the generated tool. the generated tool embeds the settings from its activated generation, so a newly added cache is available there after activation. the preflight uses rebuild-size-cache.json to share historical output nar sizes by package name across hosts through the repository. it merges local nix database observations before the dry run, retaining the largest observed size and prior shared entries. changes are synced only when committed and pushed. a previous output of at least 768 mib stops the rebuild; REBUILD_SIZE_LIMIT_MIB changes the threshold. missing history is shown with an info tag and allowed; unversioned and common generated wrapper steps are counted together. this is a size heuristic, not a build time prediction, and can miss slow builds or flag fast builds. the current nix build plan is still evaluated on every run because the store, configuration, and cache availability can change. changes to nix's database schema may require updating the helper.
